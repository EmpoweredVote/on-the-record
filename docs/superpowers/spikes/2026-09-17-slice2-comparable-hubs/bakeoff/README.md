# Source-discovery bakeoff (SPIKE)

Compares three engines for the on-the-record source-discovery hunt -- finding
comparable common-question sources for a race (debates/forums, full
interviews, written questionnaires/guides/voter pamphlets) -- against an
8-race hand-labeled ground truth (`ground_truth.json`, distilled from
`../eval/*.md`).

**This is a throwaway SPIKE, not production.** It lives entirely in the
scratchpad, is not committed, and does not modify anything in the
on-the-record repo -- it only imports `src.llm_providers` / `src.config` /
`gui.env` from the repo to reuse the existing OpenRouter plumbing.

## Files

| File | What it is |
|---|---|
| `ground_truth.json` | Machine-readable ground truth, 8 races, distilled from `../eval/*.md`. Only sources the eval files marked `exists: yes/partial` with a URL. |
| `common.py` | Shared helpers: repo-root sys.path setup, JSON-array extraction from LLM text, injection-safety prompt text, rounding. |
| `hubs.json` | DATA: known source hubs (global + per-state + generic local hub types) that engine_c.py directs its search at. Update this list independently of any code as hubs go dead/get renamed or new states are added. |
| `fixtures.py` | Deterministic canned data used ONLY by `--dry-run` -- documented in-file. |
| `engine_a.py` | Engine A: bounded Tavily search-agent loop (SEARCH/FETCH/FINAL text protocol over `src.llm_providers.get_provider`). |
| `engine_b.py` | Engine B: one (or two) OpenRouter chat calls with the `web` plugin enabled. |
| `engine_c.py` | Engine C: HUB-DIRECTED variant of engine_a's loop -- same bounded SEARCH/FETCH/FINAL protocol, but the agent is handed a `hubs.json`-derived "KNOWN HUBS TO CHECK" list and told to search those first. Raised caps (8 searches / 6 fetches / 12 turns) to afford probing more hubs. |
| `judge.py` | LLM judge: scores one engine's found-list against a race's ground truth (recall, precision, trap counts). |
| `bakeoff.py` | CLI entry point: runs engine(s) -> judge -> `report.md` + a printed summary table. |
| `report.md` | Generated by the last `bakeoff.py` run (committed to neither eval nor repo -- regenerate any time). |

`--dry-run` replaces every Tavily search/fetch and every OpenRouter chat
completion (all three engines + the judge) with a deterministic canned
fixture from `fixtures.py`. It runs the FULL pipeline end-to-end -- the
bounded search-agent loop actually loops (SEARCH -> FETCH -> FINAL), the
judge actually scores, the report actually renders -- with **zero network
calls and zero cost**. The resulting recall/precision numbers are NOT a real
quality comparison; they only prove the harness works. See the "Note on this

## Running it for real (the human's deliberate call -- NOT done in this session)

A real run costs money (OpenRouter + Tavily calls) and was **not** performed
while building this harness -- only `--dry-run` was exercised.

To run for real:

1. `OPENROUTER_API_KEY` -- already present in the repo's `.env.local`
   (loaded automatically via `gui.env.load_env_local()`). Used by Engine A's
   and Engine C's agent loops, Engine B's web-plugin call, and the judge.
2. `TAVILY_API_KEY` -- **not currently set anywhere in this repo.** Get one at
   https://tavily.com and add it to `.env.local` (or export it in your shell)
   before running Engine A or Engine C for real. Without it, that engine
   reports itself `"unavailable (no TAVILY_API_KEY)"` for every race and is
   skipped -- the other engine(s) and the judge still run normally.

```bash
export TAVILY_API_KEY=...   # or add to .env.local
.venv/bin/python bakeoff.py --engine all    # all 3 engines, all 8 races, real calls
.venv/bin/python bakeoff.py                 # legacy default: engines a+b only
.venv/bin/python bakeoff.py --engine b      # skip A/C if you don't have a Tavily key yet
.venv/bin/python bakeoff.py --engine c      # just the hub-directed loop
```

Real-run costs to expect: Engine A does up to 4 Tavily searches + 6 page
fetches + 8 LLM turns per race (8 races => up to 32 searches / 48 fetches /
64 LLM calls total); Engine C does up to 8 Tavily searches + 6 page fetches +
12 LLM turns per race (up to 64 searches / 48 fetches / 96 LLM calls total);
Engine B does 1-2 OpenRouter chat calls per race (8-16 total); the judge does
1 OpenRouter chat call per (race, engine) scored (up to 24 total with all
three engines). All engines use a mid-tier model
(`anthropic/claude-haiku-4.5`, via OpenRouter) -- the model id is a constant
at the top of each of `engine_a.py`, `engine_b.py`, `engine_c.py`, and
`judge.py` if you want to swap it.

## Design notes / known SPIKE shortcuts

- Ground truth only includes sources the eval files marked as actually
  existing and comparable (a debate/forum/interview/questionnaire/guide/
  voter_pamphlet with `exists: yes` or `partial` and a URL) -- background
  reporting, fact-checks, stale/no-longer-current pages, and directory-only
  hub pages were deliberately left out, matching what the hunt is actually
  supposed to find.
- Engine A's "tool use" is a simple text protocol (`SEARCH:` / `FETCH:` /
  `FINAL:`) parsed by the harness, not native OpenAI-style function calling --
  this lets it run entirely through the repo's existing
  `src.llm_providers.get_provider()` text-completion interface, per the task
  spec, instead of a separate tool-calling client.
- Engine B needs the OpenRouter-only `plugins` field, which
  `get_provider()`'s abstraction doesn't expose, so it builds its own
  `openai.OpenAI` client against the same `config._OPENROUTER_URL` +
  `OPENROUTER_API_KEY` the repo already uses.
- The judge recomputes recall/precision arithmetic itself from the judge's
  matched-urls / wrong-finds output, rather than trusting an LLM's own
  arithmetic.
- Recall/precision are pooled (micro-averaged) across all scored races per
  engine, not a simple mean of per-race ratios.
